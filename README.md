# otel-receiver-service

An [OpenTelemetry Collector](https://opentelemetry.io/docs/collector/) **metrics receiver** that reports the state of the services running on a host, with one unified metric for both Linux and Windows. It reads systemd over D-Bus on Linux and the Service Control Manager on Windows.

This repository is meant to be compiled into your own Collector distribution with the [OpenTelemetry Collector Builder (OCB)](https://opentelemetry.io/docs/collector/custom-collector/) - see [Building a custom collector](#building-a-custom-collector-with-ocb) below.

## Metrics

One metric is emitted, with one data point per service:

```
system.service.state{system.service.name="nginx"} = 4
```

| Metric                 | Unit      | Type      | Description                                          |
| ---------------------- | --------- | --------- | ---------------------------------------------------- |
| `system.service.state` | `{state}` | Gauge Int | Current state of the service, as an integer code.    |

The state codes are the same on every platform: `0` unknown, `1` stopped, `2` starting, `3` stopping, `4` running, `5` paused, `6` failed. Service names are normalized, so the `nginx.service` systemd unit and the `nginx` Windows service are both reported as `nginx`.

Full receiver documentation, including the per-platform state mapping: [`servicereceiver/README.md`](./servicereceiver/README.md) and [`servicereceiver/documentation.md`](./servicereceiver/documentation.md).

## Requirements

- Linux with systemd, or Windows (the component is not supported on macOS).
- On Linux, access to the systemd D-Bus interface (the system bus by default, or the user bus with `scope: user`).
- On Windows, the rights to open the Service Control Manager for reading. Without them the receiver logs a warning and reports nothing rather than failing the collector.

## Building a custom collector with OCB

[OCB](https://opentelemetry.io/docs/collector/custom-collector/) builds a Collector binary from a manifest that lists the components to include. Add this receiver to the `receivers` section of your manifest. Because the package lives in the `servicereceiver/` subdirectory of the module, set both `gomod` (the module) and `import` (the package).

A ready-to-use manifest is provided in [`examples/builder-config.yaml`](./examples/builder-config.yaml):

```yaml
receivers:
  - gomod: github.com/pierre-prevoteau/otel-receiver-service v0.1.0
    import: github.com/pierre-prevoteau/otel-receiver-service/servicereceiver
```

### 1. Install OCB

```bash
go install go.opentelemetry.io/collector/cmd/builder@v0.158.0
```

### 2. Build

```bash
builder --config examples/builder-config.yaml
```

This produces the binary under `./otelcol-service/` (per `dist.output_path` in the manifest).

### Using a published version vs. local source

- **Published version** - once you tag a release (`git tag v0.1.0 && git push --tags`), reference it directly with `gomod: github.com/pierre-prevoteau/otel-receiver-service v0.1.0`.
- **Local source (before publishing)** - keep the `replaces` directive in the manifest so OCB compiles your working tree instead of fetching a tag. The path is relative to the generated collector's `go.mod` (the `output_path` directory):

```yaml
replaces:
  - github.com/pierre-prevoteau/otel-receiver-service => ../
```

## Running the collector

A sample runtime config is in [`examples/otelcol.yaml`](./examples/otelcol.yaml):

```bash
./otelcol-service/otelcol-service --config examples/otelcol.yaml
```

```yaml
receivers:
  system_service:
    collection_interval: 30s
    include_services:
      - nginx
      - "postgresql*"
    exclude_services:
      - "systemd-*"

exporters:
  debug:
    verbosity: detailed

service:
  pipelines:
    metrics:
      receivers: [system_service]
      exporters: [debug]
```

## Development

The platform specific code sits behind the small `serviceProvider` interface in [`servicereceiver/provider.go`](./servicereceiver/provider.go), so the scraper, the filtering and the state mapping carry no build tags and their tests run on any operating system, including macOS.

This project uses [`mdatagen`](https://github.com/open-telemetry/opentelemetry-collector/tree/main/cmd/mdatagen) to generate the `internal/metadata` package, `documentation.md`, and the generated tests from `servicereceiver/metadata.yaml`.

```bash
# Regenerate code from metadata.yaml
make generate

# Run tests (and re-create the golden file after changing emitted metrics)
make test
make golden

# Type-check the Linux and Windows code paths from any host
make build-cross

# Tidy modules
make tidy
```

> Note: `mdatagen` cannot be installed with `go install ...@version` because its module ships with `replace` directives. The `make generate` target works around this by running it from a throwaway tool module (Go 1.24+ `go tool`).
